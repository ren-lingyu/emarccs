#+AUTHOR: aRenCoco

* 项目介绍

这是本人自用的 Emacs 配置, 只有 Nix 入口: =flake.nix= 通过 =twist.nix= 构建包含 package set 和本配置的 Emacs wrapper.

配置主体位于 =lisp/=, 是一组平铺的 =emarccs-*.el= 模块. Nix wrapper 专用的启动适配是 =lisp/emarccs-bootstrap.el=.

当前目标 Emacs 版本为 *31+*. Nix wrapper 当前使用 =pkgs.emacs-pgtk= 和 =pkgs.emacs-gtk=.

关键约定:

- =lisp/= 是配置主体的唯一 elisp 来源, 仓库根目录不放 elisp 文件. =pkgs/= 和 =tests/= 另有构建辅助脚本和测试脚本.
- =lisp/emarccs-init.el= 是配置入口, 模块加载顺序应保持稳定.
- =lisp/emarccs-early-init.el= 在 early-init 阶段由 wrapper 加载.
- =lisp/emarccs-bootstrap.el= 由 wrapper 的 =site-start.el= 加载, 只定义启动阶段调度 advice.
- =pkgs/<package>/melpa-recipe.el= 和 =override.nix= 服务 twist.nix.
- =lib/default.nix= 提供 variant 输出组装和源码唯一行定位等项目 Nix helper, 以 =llib= 与 Nixpkgs 的 =lib= 区分.
- =locks/emacs/= 由 twist.nix 维护, 当前 pgtk/gtk 共享同一 Emacs 大版本 lock.
- =tests/default.nix= 汇总五类检查, 由 flake 分别为 pgtk/gtk wrapper 生成 checks.

* 启动注入

配置不是由 Emacs 原生的 =init.el= / =early-init.el= 文件名加载的. wrapper 生成的 =site-start.el= 会:

1. 把 =lisp/= 加入 =load-path=.
2. require =emarccs-bootstrap=.
3. 在 =startup--load-user-init-file= 上安装 advice.

该 advice 在 early-init 阶段加载 =lisp/emarccs-early-init.el=, 在 init 阶段 require =emarccs-init=; 每个阶段都先加载本配置, 再调用原生实现加载真实用户对应的 init 文件. =init-file-user= 为 nil 时 (=-q=, =--no-init-file=) 会跳过本配置, 仍调用原生实现.

=emarccs-init= 保持固定的模块加载顺序, 最后加载可选的用户 =custom.el=. 原 pure-emacs / straight.el 入口已移除, 直接把仓库作为 =user-emacs-directory= 不会加载本配置.

* Nix / twist 入口

=flake.nix= 使用 =flake-parts= 和 =twist.nix= 构建 configured Emacs wrapper. 当前主要输出:

#+begin_src text
packages.<system>.emacs-pgtk-twist
packages.<system>.emacs-gtk-twist

apps.<system>.emacs-pgtk-twist-lock
apps.<system>.emacs-pgtk-twist-update
apps.<system>.emacs-gtk-twist-lock
apps.<system>.emacs-gtk-twist-update

overlays.default
formatter.<system>
#+end_src

常用命令:

#+begin_src sh
nix flake check -L --show-trace
nix build .#emacs-pgtk-twist -L --show-trace
nix run .#emacs-pgtk-twist-lock --impure
nix run .#emacs-pgtk-twist-update --impure
#+end_src

Nix wrapper 的策略:

- 不让 twist 读取真实 =init.el=.
- =initParser= 返回空 package set, 因此不依赖 =:ensure t= 推断包列表.
- =extraPackages= 来自 =pkgs/default.nix= 的显式包列表.
- =config.context= 用 flake-parts options/submodules 组织 package set、Emacs variant 和 lock 路径, packages/apps/checks 共用这些配置. =overlays.default= 在 build/host platform 相同时暴露 wrapper packages.
- =extraSiteStartElisp= 在 wrapper 的 =site-start.el= 中把 =lisp/= 加入 =load-path=, 并安装 =startup--load-user-init-file= advice.
- 本配置在真实用户 init 前加载; =--no-init-file= 仍保留 Emacs 原生命令行语义.

当前 =checks= 依赖实际 wrapper 和 package/grammar 构建产物, 所以第一次 =nix flake check= 可能较重. =nix fmt= 使用 treefmt/nixfmt 格式化 Nix 文件, 对应的格式检查也纳入 flake checks.

* Package 定义

=pkgs/default.nix= 自动发现:

- =pkgs/<package>/melpa-recipe.el=
- =pkgs/<package>/override.nix=

并显式维护 twist 使用的 package list. 本地 MELPA recipe 在仓库中保留 =melpa-recipe.el= 后缀, 再由 =pkgs/default.nix= 生成 twist 可读取的无后缀 recipe 目录.

这里使用 =runCommand + cp= 生成 regular files, 以适配当前锁定的 twist MELPA reader 对 recipe entry 类型的过滤; symlinked recipe entry 会被过滤并表现为 =Package <name> is not found=. 这是当前 registry reader 的约束.

=pkgs/assert.nix= 在 package 配置求值时检查目录约定: 每个 package 目录至少有 =melpa-recipe.el= 或 =override.nix=, 有 recipe 的包必须出现在显式 package list 中. override-only 的内置包目录也有效.

当前 override 接口:

- =input=: 作用于 twist package data, 适合补 metadata, =packageRequires=, =preBuild= 等.
- =scope.overrideAttrs=: 调整 =elispPackages= 中对应包的 derivation, 例如 =nativeBuildInputs=、patch 和 Info 文档构建.
- =scope.executablePackages=: 声明该包需要的运行工具, 由 =pkgs/default.nix= 与继承的工具列表合并并用 =lib.unique= 去重. 各包可以独立声明相同工具.

重要 override:

- =org=: 使用 tecosaur fork, 构建前生成 =org-version.el=.
- =auctex=: 通过 =scope.overrideAttrs= 注入 TeX/Perl/Git 构建依赖, 显式构建并安装 =auctex.info= 和 =preview-latex.info=.
- =citar=: 修正 generated autoload 缺少 =cl-lib= 的问题.
- =company-auctex=: 构建期设置可写 =HOME=.
- =company=: 修正源码中的 Texinfo example 排布.
- =laas=: 补充缺失依赖 =math-symbol-lists=.
- =pdf-tools=: 构建原生 =epdfinfo= 并向包暴露该程序.
- =treesit-auto=: 注入 Nix 提供的 =with-all-grammars= 库路径及必要的 language/symbol 映射.
- =dired=、=consult=、=ripgrep=、=org-texmacs=: 分别贡献 coreutils、搜索工具和启用字体支持的 TeXmacs 等运行工具.

* 测试状态

当前仓库为 pgtk/gtk 分别提供五类 flake checks:

- =startup-smoke=: 检查 wrapper =site-start.el= 中的 load-path 和 startup advice 注入, 并在 batch 中检查 bootstrap 可加载、配置入口可定位.
- =startup-order=: 用 =--batch -Q= 和最小夹具测试 bootstrap 的阶段顺序、参数/返回值转发和禁用用户 init 时的行为. 连续两轮检查 fixture 清理, 不启动交互式 Emacs 或加载完整配置; 执行限时 20 秒, 再给 3 秒强制终止宽限. 它不验证真实 Emacs 启动流程或 wrapper 注入.
- =package-availability-smoke=: 用 =locate-library= 检查显式声明包可被 Emacs 找到, 不验证包的完整运行行为.
- =elisp-byte-compile=: 独立字节编译 =lisp/= 的配置文件, 使用包 autoload 和本地 feature 占位, 不执行整套配置.
- =treesit-grammars-runtime=: 枚举产物中的 grammar 库, 检查 Emacs 可找到语言并创建 parser, 不验证真实源码解析、major mode、font-lock 或缩进.

另有 =treefmt= 检查 Nix 文件格式.

本次 pure-emacs 清理和文件平铺后, 用户运行 =nix flake check= 在 =x86_64-linux= 上通过, 包含修正后的 pgtk/gtk =startup-order= 和 =treefmt=. 其他平台未验证; 该结果也不表示完整个人配置的交互式启动已验证.

当前后续维护项:

- AUCTeX override 当前使用 =texliveMinimal.withPackages= 组合构建期 TeX 环境. 若后续 Nixpkgs 调整 TeX Live schema, 需要重新检查该 override.

* 维护注意事项

- =.gitignore= 使用倒置白名单模式. 新增可追踪文件时, 需要同时确认对应 =!pattern= 已放行.
- 修改 =lisp/emarccs-init.el= 的模块顺序时要谨慎, 当前顺序是配置初始化语义的一部分.
- 本配置与 wrapper 解耦: =lisp/*.el= 中不应引入依赖 wrapper 或 twist 的分支.
