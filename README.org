#+title: Emarccs
#+author: aRenCoco

* 项目介绍
这是本人自用的 Emacs 配置. =flake.nix= 通过 Nixpkgs 的 Emacs package scope 打包配置和第三方依赖, 并构建配置好的 Emacs wrapper.

配置主体位于 =pkgs/emacsPackages/emarccs/lisp/=, 按多文件 Elisp package 组织, 主入口是 =emarccs.el=. 配置包由 =melpaBuild= 构建, 通过 ELPA 描述文件和 autoloads 接入 package activation; wrapper 负责启动调度.

最低 Emacs 版本为 *31.1*. 提供基于 =pkgs.emacs=, =pkgs.emacs-pgtk= 和 =pkgs.emacs-gtk= 的三个 wrapper.

关键约定:

- =pkgs/emacsPackages/emarccs/= 定义 Elisp 配置包, =pkgs/emarccs/= 定义包含配置和依赖的 Emacs wrapper.
- =emarccs.el= 只加载早期和常规初始化接口, require 本身不执行配置或注册启动调度.
- =emarccs-early-init.el= 定义 =emarccs-initialize-early=, =emarccs-init.el= 定义 =emarccs-initialize=. 加载这两个文件不执行初始化.
- wrapper 的启动调度由 =pkgs/emarccs/package.nix= 生成, 各功能模块管理其内部的 hooks/advice.
- =lib/default.nix= 保留本仓库的 Nix helper 扩展入口. 通用 helper 来自 =personal-nixpkgs= input, 合并后以 =llib= 与 Nixpkgs 的 =lib= 区分.
- 源码检查由所属 package 的 =checkPhase= 执行, 独立 package tests 随 package 定义, 通过 =passthru.tests= 暴露. 顶层 =tests/default.nix= 发现 flake 层面的检查, 并通过 =llib.tests.mkChecks= 的 =checks= 参数纳入 =legacyPackages= 中各 package 的已有 tests.

* 启动注入
配置通过 wrapper 的 =site-start.el= 接入启动流程. =init-file-user= 非 nil 时, wrapper 依次:

1. 调用 =package-activate-all=, 激活安装的 Elisp packages 及其 autoloads.
2. require =emarccs=, 加载初始化函数定义.
3. 调用 =emarccs-initialize-early=, 在用户 =early-init.el= 前应用早期配置.
4. 将 =emarccs-initialize= 注册到 =before-init-hook=, 在用户 =init.el= 前执行常规配置.

用户的原生 init 文件仍由 Emacs 加载. =init-file-user= 为 nil 时, 如 =-q= / =--no-init-file= 或 batch 启动, wrapper 跳过上述 Emarccs 启动调度.

初始化成功后不重复执行, 保留用户后续覆盖. 常规初始化加载 =use-package= 并设置 =use-package-always-ensure= 为 nil, 按固定顺序加载内部模块, 最后设置 =custom-file= 并加载用户 Emacs 目录中可选的 =custom.el=. 重入时跳过, 失败时不置完成标记.

三个 wrapper 共用 =pkgs/emarccs/package.nix= 的构造逻辑, 使用 =emacsPackagesFor= / =withPackages= 加入配置包和 GNU coreutils. GTK/PGTK 变体通过 =override= 选择对应的基础 Emacs. 配置依赖从该 Emacs 对应的 package scope 解析.

=overlays.default= 直接导出 =pkgs/default.nix= 组合的 overlay, 包含本地 Elisp package 定义、覆盖及三个 wrapper. flake 自身导入 Nixpkgs 时也使用同一 overlay, =packages= 直接继承其中的 wrapper. 在其他 flake 中将本仓库作为 =emarccs= input 后, 可以这样使用:

#+begin_src nix
  pkgs = import inputs.nixpkgs {
    inherit system;
    overlays = [ inputs.emarccs.overlays.default ];
  };
#+end_src

=personal-nixpkgs= 提供 package/overlay 发现和测试聚合等通用 helper, 其 =nixpkgs=, =flake-parts= 和 =treefmt-nix= 依赖 follows 本仓库对应输入. =llib= 使用 =mergeAttrsRecursive { allowOverrides = false; }= 合并共享库中的 =packages=, =tests= 和本地扩展, 重叠的叶节点定义会报错.

* Package 定义
=pkgs/default.nix= 通过 =llib.packages.mkOverlays= 递归发现 =overlay.nix=, 组合本地覆盖. 共享库为顶层 =emacsPackages/= 目录提供内置聚合规则, 通过 =emacsPackagesFor= 的 =overrideScope= 将后代 overlay 应用到对应 Emacs 的 package scope; 本仓库无需单独定义该目录的聚合 overlay.

由共享库加载的 =overlay.nix= 和 =test-overlay.nix= 都采用 constructor 协议. 无需构造参数时, 使用如下形式:

#+begin_src nix
  { }: final: prev: {
    emarccs = final.callPackage ./package.nix { };
  }
#+end_src

外层函数由共享库实例化, 返回标准的 =final: prev: ...= overlay. 需要共享 helper 时通过 =extraArgs= 传入, 例如 wrapper 的 =mkChecks=. 对外导出的 =overlays.default= 仍按普通 Nixpkgs overlay 使用.

- 独立构建的包保留 =package.nix=, 由同目录的 =overlay.nix= 使用 =callPackage= 接入.
- 仅覆盖已有包的目录可只保留 =overlay.nix=. 例如 =consult=, =ripgrep= 和 =treesit-auto= 直接调用原包的 =overrideAttrs=.
- =legacyPackages= 按 overlay 文件和包集合中的 derivation 属性导出本地定义或覆盖的包, 不要求存在 =package.nix=.
- =pkgs/emacsPackages/emarccs/package.nix= 显式声明配置所需的 =packageRequires=. 本地配置和自定义 Elisp packages 使用 =melpaBuild=, 显式指定 =files= 和 =melpaVersion=, 生成 ELPA 描述文件及 autoloads.
- 文件选择通常使用 =(:defaults)=. 额外运行资源要写入 recipe, 例如 =org-texmacs-worker.scm=; 只按主包名前缀选择文件可能漏掉其他入口库.

主要包适配和运行依赖:

- =org=: 使用官方 =bzg/org-mode= 源码, 构建 autoloads 时显式指定 Org/Git 版本.
- =org-include-inline= 和 =org-workbench=: 在本地包定义中应用源码补丁.
- =consult=: 通过 =propagatedUserEnvPkgs= 提供 GNU grep 和系统 ripgrep.
- =ripgrep=: Elisp 包传播系统 ripgrep. 系统程序从外层 Nixpkgs 取值, 避免与同名 Elisp package 混淆.
- =treesit-auto=: 传播对应 scope 的 =with-all-grammars=, 并补充 grammar 库名及初始化符号映射.
- =texmacs-with-fandol-and-math-syntax=: 基于 Org-TeXmacs overlay 提供的 =texmacs-with-gotor-support= 进行 =overrideAttrs=, 在 =TeXmacs/fonts/truetype/fandol/= 安装 Fandol OpenType 字体, 在 =TeXmacs/packages/emarccs/= 安装纯 Nix 生成的 =emarccs-math.ts=. 保留 GoToR 修复, 不修改内置 style, 不替换原有 =pkgs.texmacs=, 不另设字体 wrapper. 通过 default overlay 提供, 并导出到 =legacyPackages.<system>.texmacs-with-fandol-and-math-syntax=.
- =org-texmacs=: 默认使用 =texmacs-with-fandol-and-math-syntax=, 将程序路径写入配置默认值, 并把 Scheme worker 与 Lisp 文件一起打包. =texmacs-with-fandol-and-math-syntax= 已安装 =emarccs-math= style, 启用该语法时把 =org-texmacs-document-style= 设为 ='("generic" "emarccs-math")=; 调用方仍可通过 =org-texmacs.override { texmacs = ...; }= 替换程序.
- Dired 所需的 GNU coreutils 直接加入 wrapper 的 =withPackages= 列表.

传播的程序和 grammar 库由 Nixpkgs wrapper 接入运行时查找路径.

** TeXmacs 数学语法
=pkgs/texmacs-with-fandol-and-math-syntax/math/registry.nix= 定义原生定界符, =math/default.nix= 生成 package 文本. 生成器通过纯 Nix 函数计算字符串, =writeText= 将其变为构建依赖, =postPatch= 仅安装生成的文件; 不需要 Elisp 或其他外部代码生成器, 也不需要 IFD. 修改定义会重新构建最终的 TeXmacs derivation.

普通定界符采用 =l<count><kind>= / =r<count><kind>= 编码, 单层另有省略数字的别名; =n= 是不可见定界符. 47 个代码可任意有序组合, 只排除 =nn=. 名称直接连接两个代码, 如 =lprp=, =lpn=, =l2vr2v=. 每种组合提供单参数宏和 =concat-= 前缀的变参宏, 共 4416 个定界符宏; 另提供 =application=, 连接函数、数学空格与参数.

#+begin_src scheme
  (lprp (frac "1" "2"))
  (concat-lprp "x" "+" "y")
  (application "f" (lprp "x"))
#+end_src

生成的 style 可单独构建检查, 无需构建 TeXmacs:

#+begin_src sh
  nix build --option allow-import-from-derivation false \
    .#legacyPackages.x86_64-linux.texmacs-with-fandol-and-math-syntax.mathStyle
#+end_src

* 检查
测试按所验证的 package 组织. 源码检查在 package 构建中执行, 对完整安装产物的检查作为独立 derivations 通过 =passthru.tests= 暴露. 顶层 flake checks 负责聚合导出 packages 的独立测试, 以及验证 flake 自身的导出契约和本地 Nix helper.

** 测试执行状态报告
本地 =lib/withProgress.nix= 通过 =llib.tests.withProgress= 提供 Bash 代码生成 helper, 与 =mkChecks= 的测试发现和聚合机制相互独立. 它不构造 derivation, 也不需要额外的计时工具. 当前先通过独立的 flake check 验证该 helper, 尚未修改各 package 的测试执行入口.

#+begin_src nix
  withProgress {
    name = "example";
    interval = 10;
    text = "emacs --batch -Q ...";
  }
#+end_src

- =name= 为非空字符串, =interval= 为正整数秒数, 默认为 10. =text= 接收 Bash 源代码字符串或 Nix path; path 在求值时通过 =builtins.readFile= 读取并内嵌, 不作为独立脚本执行.
- 生成的代码要求 Bash >= 5.3. 开始时打印任务名, 运行期间按 interval 定期报告经过的时间, 结束时打印成功或失败及总耗时, 并保留原代码块的退出状态. 不设置超时, 不管理任务的进程树.
- 同时报告 =EPOCHREALTIME= 的有符号差值 (保留六位小数) 和 =BASH_MONOSECONDS= 的整数秒差值. 前者可能受系统时钟调整影响; 后者在平台不支持单调时钟时由 Bash 回退到实时时钟. 不尝试校正两者的差异.
- 原代码直接继承 stdout, stderr, Shell 变量和当前目录, 不通过输出代理或缓存; 状态日志追加到 stderr, 原代码内部的重定向保持有效. 两层 subshell 隔离 reporter 和原代码的变量、目录及 trap 修改, 原代码的 Shell 选项和错误传播遵循 Bash 的通常规则 (包括 =errexit= 在条件上下文中的行为).
- 使用 =coproc= 和 =read -t= 实现周期性报告; 原代码结束时关闭控制管道并回收 heartbeat, 不等待下一个报告间隔. 构建取消及任务后代进程的管理由 Nix 负责. Heartbeat 表示任务尚未结束, 不表示任务取得实际进展; 它也会影响 Nix 的 =max-silent-time= 判断.

=tests/with-progress/= 验证字符串及 path 输入, 输出保留, 退出状态, Shell 隔离, 空代码, 周期性报告和 =exec= 等行为. 可以通过 =nix build .#checks.x86_64-linux.with-progress -L= 单独构建.

** Elisp 配置包
=pkgs/emacsPackages/emarccs/package.nix= 通过 =melpaBuild= 构建配置包, 由其正常的安装及编译流程检查 Elisp 编译错误, 不再额外运行独立的 =elisp-byte-compile= 测试. 编译警告仍不作为失败条件.

配置包启用 =doCheck=, 在 =checkPhase= 中分别启动独立的 batch Emacs 进程执行下列源码检查. =package-lint= 通过当前 Emacs package scope 的 =checkInputs= 引入, 由 Emacs setup hook 和 =package-activate-all= 提供依赖查找环境, 不加入 =packageRequires= 或配置的运行依赖, 也不手写 package 的版本化安装目录. 测试目录独立于 =src=, 不纳入 MELPA package archive.

- =initialization=: 由原 =startup-order= 中的四项 ERT 用例组成, 验证接口加载无配置副作用、早期及常规初始化只执行一次、模块顺序、初始化重入和失败后重试. 直接使用配置包源码, 不需要构建最终 wrapper.
- =package-lint=: 检查全部配置源码, 以 =emarccs.el= 为主文件. 仅豁免功能配置中的保留键位和 =with-eval-after-load= 两类诊断并逐项输出; 其他诊断均失败, 三个入口/初始化接口文件无此豁免.

** Emarccs wrapper tests
=pkgs/emarccs/tests/default.nix= 通过 =mkChecks= 构造独立的测试 scope, 发现各目录中的 =test-overlay.nix=, 并通过测试 scope 的 =callPackage= 加载同目录的 =test.nix=. 使用当前 wrapper 的最终 derivation 及其对应的配置包. =pkgs/emarccs/package.nix= 通过 =passthru.tests= 暴露这些测试, 并保留底层包的已有 tests. 默认、GTK 和 PGTK wrapper 共用该定义, 各自通过 =override= 实例化测试, 不单独维护测试源码.

- =startup-smoke=: 验证禁用用户初始化时配置不执行、require 入口保持惰性、配置库来自指定安装产物. 随后执行实际 wrapper 启动表达式, 保留真实 package activation, 仅替换配置初始化函数, 检查激活结果和调度.
- =startup-order=: 原测试中与 wrapper 有关的三项 ERT 用例, 用实际生成的 =site-start.el= 和替身验证 hook 注册不叠加、用户 init 前的执行顺序及禁用用户 init. 不启动交互式 Emacs.
- =package-availability-smoke=: 根据配置包的 =packageRequires= 用 =locate-library= 检查依赖可被 Emacs 找到, 不验证包的完整运行行为.

可以通过 wrapper 的 =tests= 属性直接构建相应测试:

#+begin_src sh
  nix build .#legacyPackages.x86_64-linux.emarccs.tests.startup-smoke
  nix build .#legacyPackages.x86_64-linux.emarccs-pgtk.tests.startup-order
  nix build .#legacyPackages.x86_64-linux.emarccs-gtk.tests.package-availability-smoke
#+end_src

** Tree-sitter grammar runtime test
=pkgs/emacsPackages/treesit-auto/tests/= 定义 =grammars-runtime= 测试, 由对应 Emacs scope 中的 =treesit-auto= override 通过 =passthru.tests= 暴露. 测试使用只显式包含最终 =treesit-auto= 及其传播依赖的 Emacs wrapper, 不依赖完整 Emarccs wrapper.

测试枚举指定产物中的 grammar 库, 检查 Emacs 的实际查找路径可找到语言并创建 parser, 不向查找路径补目录; 不验证真实源码解析、major mode、font-lock 或缩进. 测试断言与原 =treesit-grammars-runtime= 相同, 但现在验证的是 =treesit-auto= 的依赖传播及运行时行为, 而非完整 Emarccs 环境.

#+begin_src sh
  nix build .#legacyPackages.x86_64-linux.emacsPackages.treesit-auto.tests.grammars-runtime
#+end_src

** Flake checks
=tests/default.nix= 接收 =config.legacyPackages= 导出的有限 package tree, 递归提取 derivation 叶节点的 =tests=, 保留 namespace 结构. 没有独立测试的 package 对应空测试集合. 一次调用 =llib.tests.mkChecks=, 通过 =checks= 纳入上述测试树, 同时发现顶层测试目录中的 =test-overlay.nix=. =mkChecks= 合并测试树, 以 =-= 为分隔符平铺属性路径并检查名称冲突. 新增导出 package 的 =passthru.tests= 无需修改顶层测试列表. 顶层 =test-overlay.nix= 定义独立的 =with-progress= helper 测试和依赖 flake 上下文的 =overlay-equivalence= 测试:

- =overlay-equivalence=: 从同一份 Nixpkgs 独立导入只应用公开 default overlay 的包集合, 递归比较 =legacyPackages= 中每个 package 与对应属性路径下的 package 的 =drvPath=. 缺少对应 package、求值失败或 derivation 不一致都会失败; 通过后仅生成一个空检查产物, 不重复构建被比较的 packages.

例如 =emarccs-pgtk-startup-order= 和 =emacsPackages-treesit-auto-grammars-runtime= 分别对应 wrapper 的测试及默认 Emacs scope 中 =treesit-auto= 的测试. 三个 wrapper 各自的 tests 均纳入, =treesit-auto= 不再经三个 wrapper 重复纳入. 所有导出 packages 的 tests (包括继承的上游 tests 和 TeXmacs tests) 均参与聚合.

配置初始化 ERT 和 =package-lint= 随各自的配置包构建执行, 不再导出独立的源码检查; =elisp-byte-compile= 已由正常构建取代. 本仓库定义的 Emacs 测试不设置进程级超时, 使用标准构建环境中的工具, 需要限制构建时间时由 Nix 构建设置控制. 另有 =treefmt= 格式检查. 首次全量检查可能需要构建 wrapper, 依赖, grammar 和 TeXmacs 产物.

查看最终导出的 checks:

#+begin_src sh
  nix eval .#checks.x86_64-linux --apply builtins.attrNames --json
#+end_src

** TeXmacs package tests
独立检查定义于 =pkgs/texmacs-with-fandol-and-math-syntax/tests/=, 由该 package 的 =passthru.tests= 暴露, 并随 =legacyPackages= 中的其他 package tests 自动纳入 flake checks. 这些测试独立于 Emacs wrapper 的测试组织:

- =resources=: 核对生成的 4417 个宏定义及代表性源码, 比较安装的 style 与生成文件, 比较安装的 Fandol 字体与来源文件.
- =math-syntax=: 直接调用最终 TeXmacs, 使用独立的配置目录渲染自定义宏和等价原生表达式的 native 文档, 比较 PDF 文本及单页 raster 输出. 不依赖 Emacs 或 Org-TeXmacs, 不验证全部定界符的字体字形. 保留文档、PDF、文本、raster 和日志供检查.

通过 =legacyPackages= 直接构建 package tests:

#+begin_src sh
  nix build .#legacyPackages.x86_64-linux.texmacs-with-fandol-and-math-syntax.tests.resources
  nix build .#legacyPackages.x86_64-linux.texmacs-with-fandol-and-math-syntax.tests.math-syntax
#+end_src

* 维护注意事项
- =.gitignore= 使用倒置白名单模式. 新增可追踪文件时, 需要同时确认对应 =!pattern= 已放行.
- 修改 =pkgs/emacsPackages/emarccs/lisp/emarccs-init.el= 的模块顺序时要谨慎, 当前顺序是配置初始化语义的一部分.
- 新增或调整 Elisp 包时, 同时核对 =packageRequires=, MELPA recipe 的文件选择、ELPA metadata/autoloads 和所需运行资源.
